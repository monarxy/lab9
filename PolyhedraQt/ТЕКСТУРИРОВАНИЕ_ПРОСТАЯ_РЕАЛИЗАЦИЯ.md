# Текстурирование: упрощённая реализация

В этой версии оставлен только базовый алгоритм, необходимый для задания: загрузка изображения `QImage`, UV-координаты углов граней, разбиение граней на треугольники, барицентрическая интерполяция UV и выбор ближайшего пикселя текстуры.

## 1. Что хранится в модели

В `geometry/Polygon.h` у каждой грани есть `textureCoordinates` — список пар `(u, v)`. Элемент с индексом `i` относится к углу грани `indices[i]`.

UV хранятся именно для углов граней, а не в общей геометрической вершине. Это позволяет одной геометрической вершине при необходимости иметь разные координаты текстуры на разных гранях. Для простых правильных многогранников этого достаточно.

## 2. Откуда берутся UV

OBJ-файл теперь используется только для геометрии: записи `v` задают координаты вершин, записи `f` — состав граней. Текстурные записи `vt` не читаются и не записываются.

Когда модель рассчитывает нормали (`Polyhedron::calculateNormals()` в `geometry/Polyhedron.cpp`), для каждой грани автоматически создаются простые UV. По нормали определяется ось, на которую грань ориентирована сильнее всего. Затем для UV используются две остальные координаты вершин. Минимальные и максимальные значения этих координат переводятся в диапазон от 0 до 1.

Это простая плоская проекция отдельно для каждой грани. Она подходит для демонстрации текстурирования тетраэдра, куба и октаэдра; это не универсальная развёртка сложных моделей.

## 3. Загрузка изображения

В `ui/MainWindow.cpp` кнопка «Загрузить изображение текстуры» открывает `QFileDialog`. Выбранный файл читается в `QImage`. Если изображение загрузилось успешно, оно передаётся в `PolyhedronWidget::setTexture()`.

`setTexture()` сохраняет изображение в `textureImage` в формате `QImage::Format_ARGB32`. Флажок «Использовать текстуру» включает или выключает её наложение. Встроенная тестовая шахматная текстура удалена: теперь используется именно изображение, выбранное пользователем.

## 4. Разбиение грани на треугольники

Растеризатор находится в `render/PolyhedronWidget.cpp`, в `PolyhedronWidget::paintEvent()`.

Грань может содержать три, четыре или больше вершин. Она разбивается на треугольники веером: первая вершина грани становится общей, а остальные вершины образуют треугольники `(0, 1, 2)`, `(0, 2, 3)` и так далее.

Таким образом, четырёхугольник обрабатывается как два треугольника. Отдельное восстановление параметров четырёхугольника не требуется.

## 5. Барицентрические координаты пикселя

Для каждого треугольника программа перебирает пиксели внутри его экранного ограничивающего прямоугольника. Проверяется центр пикселя `(x + 0.5, y + 0.5)`.

По экранным координатам трёх вершин вычисляются три барицентрических веса `w0`, `w1`, `w2`. Они показывают вклад каждой вершины в положение пикселя:

- `w0 + w1 + w2 = 1`;
- внутри треугольника все три веса неотрицательны;
- на вершине один вес равен 1, остальные — 0.

Если хотя бы один вес отрицательный, пиксель находится вне треугольника и пропускается.

Для перспективной проекции веса дополнительно корректируются с учётом глубины вершин (`1 / z`). Это нужно, чтобы UV и другие атрибуты интерполировались корректно при перспективном отображении. В ортографической проекции используются обычные барицентрические веса.

## 6. Интерполяция UV

После получения весов UV пикселя вычисляются как взвешенная сумма UV трёх вершин:

`u = w0 * u0 + w1 * u1 + w2 * u2`

`v = w0 * v0 + w1 * v1 + w2 * v2`

Именно это и есть интерполяция текстурных координат внутри грани. Для каждого пикселя треугольника получается собственная пара `(u, v)`.

## 7. Получение цвета текстуры

Функция `sampleTextureNearest()` получает изображение и координаты `(u, v)`.

1. Координаты приводятся к повторяющемуся диапазону `[0, 1)`.
2. Координата `u` переводится в столбец изображения.
3. Координата `v` переводится в строку изображения. Вертикальная координата инвертируется, потому что в изображении начало координат находится сверху, а в UV обычно снизу.
4. Из `QImage` считывается цвет одного пикселя через `pixelColor(x, y)`.

Это выбор ближайшего пикселя (nearest sampling). Цвета соседних пикселей не смешиваются. Билинейная фильтрация текстуры удалена.

## 8. Сочетание с освещением

Сначала для пикселя определяется цвет выбранного режима освещения:

- «Гуро (Ламберт)» — интерполируется цвет, рассчитанный в вершинах;
- «Фонг (Toon shading)» — интерполируется нормаль, после чего рассчитывается ступенчатое освещение.

Если текстура включена, цвет освещения умножается на цвет выбранного пикселя текстуры (`multiplyColors`). Поэтому текстура задаёт основной рисунок поверхности, а освещение влияет на её яркость.

## 9. Видимость граней, глубина и преобразования

Перед растеризацией сохраняется отсечение нелицевых граней (back-face culling): грани, нормаль которых направлена от камеры, не рисуются. Для определения видимого ближайшего пикселя используется Z-буфер.

Преобразования объекта продолжают работать: перенос, вращение, масштабирование, отражение и вращение вокруг заданной оси изменяют геометрические вершины. UV при этом не пересчитываются — они остаются привязанными к соответствующим углам граней, поэтому текстура перемещается и поворачивается вместе с объектом.

## 10. Что намеренно удалено

- билинейная фильтрация текстуры;
- mip-mapping и трилинейная фильтрация;
- анизотропная фильтрация;
- вычисление производных UV;
- обратное восстановление параметров четырёхугольника;
- дополнительные способы сглаживания текстуры и 2x-суперсэмплинг;
- чтение и запись UV-координат `vt` в OBJ.

Загрузка `QImage`, UV на углах граней, интерполяция UV, выбор цвета текстуры, отсечение нелицевых граней, Z-буфер, освещение и преобразования сохранены.
